# Backend implementation plan — agreed decisions

Agreed with the project owner on 10 November 2026. This file records the
decisions that refine [backend-plan.md](../api/backend-plan.md) and the
[Claude backend brief](claude-backend-brief.md). Where they differ, this file
wins. Track progress in [backend-progress.md](backend-progress.md).

## Decisions

| Topic             | Decision                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repository layout | Keep the monorepo: `apps/web` (Next.js), `apps/api` (Fastify), `apps/media-worker`, shared `packages/*`. No split repositories.                                                                                                                                                                                                                                                       |
| Roles             | Pastor and Admin accounts are fixed: created by the `staff:add` operator command, never by sign-up. Anyone may sign up, always as Member. Role changes later only by Pastor through the API.                                                                                                                                                                                          |
| Sign-in           | Passwordless for everyone: six-digit email code (any email provider, no Gmail needed), Google login, and passkeys. No passwords, so no reset-password flow.                                                                                                                                                                                                                           |
| Google linking    | A Google login may attach to an existing account with the same email only when Google reports the email as verified.                                                                                                                                                                                                                                                                  |
| Sessions          | Auth.js database sessions (revocable). Suspension deletes sessions and blocks sign-in.                                                                                                                                                                                                                                                                                                |
| Website ↔ API     | Next.js `/api/v1/*` gateway validates the session and sends Fastify a 60-second signed identity assertion (HS256, audience `grace-api`). Fastify reloads the user and status on every request.                                                                                                                                                                                        |
| Publishing        | Immediate. No submit/approve endpoints. Revisions + restore.                                                                                                                                                                                                                                                                                                                          |
| Email delivery    | Resend free tier, sending from the church's own (already paid) domain after DNS verification. Development prints codes to the API/web console.                                                                                                                                                                                                                                        |
| File storage      | S3-compatible code. Owner is willing to pay for Amazon S3; recommended setup is S3 in the AWS Auckland region with CloudFront in front for video. Cloudflare R2 remains a drop-in alternative. Chosen at Phase 2.                                                                                                                                                                     |
| Calendar          | A: one-way sync from the site to a public church Google Calendar via a Google service account (Phase 3b). Then B: members who link Google can have their own bookings added to their personal Google Calendar (after launch; needs Google OAuth verification for calendar scopes). Members without Google keep .ics export and the public calendar subscription. Office 365 not used. |
| Background jobs   | pg-boss on PostgreSQL (no extra service).                                                                                                                                                                                                                                                                                                                                             |
| Validation        | Zod schemas on the server for every request body and query.                                                                                                                                                                                                                                                                                                                           |
| Hosting           | Chosen in Phase 6. Development and staging can run on free tiers.                                                                                                                                                                                                                                                                                                                     |

## Working agreement (Claude and Codex)

- One branch per phase (`backend-phase-N`), merged to `main` after review.
- Update `backend-progress.md` at the end of every working session: what is done, what is next, commands to run, open issues.
- Packages are installed on the owner's Mac with `pnpm install` (native binaries are macOS builds).
